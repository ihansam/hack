# drill — 첫 1시간

사람은 절차를 외우지 않는다. 단계마다 사람이 할 일을 네가 한 줄로 안내한다. 답은 핵심만.

요청에 "따라가기"가 있으면 **B**, 아니면 **A**.

## A. 착수 (작업 세션)
구현은 빠르다. 첫 1시간은 이해·SPEC·목업·계획에 쓴다.
1. `date`로 시작 시각을 본다. 제한 시간은 과제 문서에 없을 때만 한 번 묻는다. STATUS.md를 만들고 맨 위에 시작·마감·결정 확인(1/3)·동결(5/6) 시각을 적는다.
2. 사람에게 그대로 보여준다(이하 "따라가기 안내"):
   > **새 창**에서 가벼운 모델로 세션을 열고 `$drill 따라가기`를 입력하세요(20~30분). 원문을 읽고 입력 한 건을 따라가며 문제를 익히는 동안 여기선 SPEC·목업·계획을 씁니다. 끝나면 마지막 출력을 이 창에 붙여넣으세요.
3. 그동안 혼자 한다. 모호한 것은 되돌리기 쉬운 기본값으로 정해 DECISIONS.md에 `agent·잠정`으로 적고 넘어간다.
   - SPEC 초안: 과제 문서·환경 확인 → 대조 두 가지 → SPEC.md 초안 → 전략(필수/선택, 시간 배분, 시간이 모자라면 버릴 순서).
     - 요구 × 문서: 과제 요구 중 방법·범위가 정해지지 않은 문장(예: "초기화할 수 있다")
     - 규칙 × 데이터: 기준 문서의 규칙마다 걸리는 행 수를 스크립트로 세고, 규칙만으로 판정이 안 되는 행을 모은다(빈 값·중복·정정·순서·경계 시각·필드 간 불일치). 통째로 읽지 않는다
   - 담당자 질문은 SPEC 초안과 함께 바로 `[전달]`로 보여준다(따라가기를 기다리지 않는다). 질문마다 `데이터 예시 ID · 건수 · 기준 문서 위치 · 추천 기본값`, 과제 문서로 답이 되는 것은 뺀다. 안내: "담당자에게 전달하고 답을 이 창에 붙여넣으세요."
   - 답을 기다리는 동안, 과제에 화면이 있으면 목업: `mockup/` 정적 HTML 한 장, 실제 데이터 1~2건, 화면·역할별 구역, 잠정 기본값은 화면에 `잠정` 표시. 앱 코드와 섞지 않는다. 목업에서 새로 나온 애매한 점은 추가 `[전달]`.
4. 담당자 답은 원문 그대로 SPEC에 넣는다. "모른다·편하신 대로"면 `agent·잠정`과 이유를 적고 결정 확인 때 다시 본다. 답이 모두 반영되면 SPEC을 확정한다. STATUS.md "다음"에 `계획 — drill A 4부터`를 적고 "새 세션에서 '계획 진행하자'를 입력하세요(여기서 이어가도 됩니다)"라고 안내한다. 계획은 이렇게 쓴다:
   - Epic부터: STATUS.md에 `E1 이름 — 하는 일·완료 기준`을 한 줄씩. Epic 하나는 30~60분 크기(E1 = 입력→출력 최소 흐름, 마지막 Epic = 제출 점검).
   - 이어서 Epic마다 `plans/E<n>-<이름>.md`에 Task를 쓴다. Task 하나 = 한 세션 분량, `T<m> 제목` 아래 하위 체크박스와 검증 명령.
5. 4가 끝났는데 블록이 없으면 "SPEC 확정·목업·계획 완료(파일 경로)"라고 알리고 따라가기 안내를 다시 보여준 뒤 기다린다. 블록 없이 구현 요청이 오면 따라가기 안내에 `바로 구현하려면 "건너뛰기"`를 붙여 한 번 더 보여준다. 답을 STATUS.md에 `따라가기: 진행 중 / 완료 / 건너뜀(시각)`으로 적고, 이 줄이 있으면 다시 묻지 않는다.
6. 블록이 오면 용어·기준 건을 SPEC에 반영하고, 새로 나온 애매한 점만 추가 `[전달]`한다. 전략·Epic 목록을 5줄 이내로 보여주고, 다음은 새 세션에서 `E1 T1`이라고 안내한다.

## B. 따라가기 (사람이 문제를 익히는 세션)
목적은 사람이 원문과 실제 데이터를 직접 보고 문제를 머리에 넣는 것이다. 요약은 흐름 3줄까지만. 코드·파일은 쓰지 않는다(작업 세션이 같은 문서를 쓰고 있다). 30분 안에 끝낸다. 화면이 작으니 한 번에 한 화면 분량으로 답한다.
1. `date`로 시작 시각을 본다. 과제 안내·기준 문서·데이터 목록을 본다. 데이터는 `head`·`wc`로만.
2. 지도를 보여준다:
   - 흐름 3줄: 입력 → 처리 → 출력, 누가 무엇을 하나(원문 위치)
   - 요구 목록: 필수/선택과 원문 위치
   - 결과를 쓰는 사람·이해관계자(원문에 있으면)
   - 낯선 용어 목록(풀이 없이)
   - 읽을 순서: 파일·절 3개 이내

   안내: "이 순서로 원문을 읽고, 막히는 용어는 물어보세요. 다 읽으면 '다음'." 용어를 물으면 한 줄로 풀고 원문 위치를 붙인다. 개념은 실제 데이터 한 행과 기준표 행을 나란히 놓고 설명한다. 질문에 답할 때마다 끝에 "지금 읽을 곳: …" 한 줄을 붙인다.
3. 규칙이 두세 개 걸리는 평범한 입력 후보 2~3개를 한 줄씩 보여주고 고르게 한다("알아서"면 네가 고른다).
4. 그 건의 원문 행을 보여주고, 처리 단계 전체를 표 하나로 보여준다: `단계 | 규칙(원문 위치) | 이 건의 값`. 처음 나온 용어·산식은 칸 안에 한 줄로 푼다. 단계마다 멈추지 않는다.
   이어서 판단이 갈리는 지점 2개만 묻는다(기준 문서만으로 결론이 안 나거나 틀리기 쉬운 곳). 답하면 대조하고, "모름"이면 바로 값을 보여준다.
5. 끝나면 작업 세션에 붙여넣을 블록 하나를 출력하고 "이 블록을 작업 세션에 붙여넣으세요. 작업 세션이 기준 건을 SPEC에 반영하고 담당자 질문을 정리합니다"라고 안내한다:
   - 용어: `용어 | 뜻 | 원문 위치`
   - 담당자 질문 후보: 기준 문서로 답이 안 되는 지점과 해당 데이터 건수
   - 기준 건: 입력 식별자 · 단계별 값 · 최종 결과(최소 흐름의 기대값이 된다)
