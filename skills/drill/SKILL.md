# drill — 첫 1시간

사람은 절차를 외우지 않는다. 단계마다 사람이 할 일을 네가 한 줄로 안내한다. 답은 핵심만.

요청에 "따라가기"가 있으면 **B**, 아니면 **A**.

## A. 착수 (작업 세션)
구현은 빠르다. 첫 1시간은 이해·SPEC·계획에 쓴다. **따라가기 블록과 담당자 답(또는 "질문 없음")을 받기 전에는 구현을 시작하지 않는다.** 사람이 "건너뛰기"라고 하면 진행하고 STATUS.md에 적는다.
1. `date`로 시작 시각을 본다. 제한 시간은 과제 문서에 없을 때만 한 번 묻는다. STATUS.md를 만들고 맨 위에 시작·마감·결정 확인(1/3)·동결(5/6) 시각을 적는다.
2. 사람에게 그대로 보여준다:
   > 새 창에서 가벼운 모델로 세션을 열고 `$drill 따라가기`를 입력하세요. 원문을 읽고 입력 한 건을 따라가며 문제를 익히는 동안 여기선 SPEC·계획을 씁니다. 끝나면 마지막 출력을 이 창에 붙여넣으세요.
3. 그동안 혼자 한다: 과제 문서·데이터·환경 확인 → SPEC.md 초안 → 전략(필수/선택, 시간 배분, 시간이 모자라면 버릴 순서) → Epic 분해(STATUS.md, `plans/`). 모호한 것은 되돌리기 쉬운 기본값으로 정해 DECISIONS.md에 `agent·잠정`으로 적고 넘어간다.
   과제에 화면이 있으면 이어서 목업을 만든다: `mockup/` 정적 HTML 한 장, 실제 데이터 1~2건, 화면·역할별 구역, 잠정 기본값은 화면에 `잠정` 표시. 앱 코드와 섞지 않는다.
4. 블록이 오기 전에 3이 끝나면 이렇게만 안내하고 기다린다:
   > SPEC 초안 완료(내용 채움)·목업 `mockup/…`. 확정은 따라가기 블록을 받은 뒤 합니다. 따라가기가 끝나면 목업을 열어 보세요. 블록 없이 진행하려면 "건너뛰기".
   사람이 과제 내용을 물으면 3줄로 답하고, 따라가기 전이면 따라가기를 다시 안내한다.
5. 블록이 오면 용어·기준 건을 SPEC에 반영하고, 담당자 질문을 정리해 보여준다(블록·목업에서 나온 애매한 점 포함. 과제 문서로 답이 되는 것은 빼고, 해당 데이터 건수를 붙인다).
6. 담당자 답을 원문 그대로 SPEC에 넣고 확정한다. 전략·계획을 5줄 이내로 보여주고, 다음은 "입력→출력 최소 흐름 착수"라고 안내한다.

## B. 따라가기 (사람이 문제를 익히는 세션)
목적은 사람이 원문과 실제 데이터를 직접 보고 문제를 머리에 넣는 것이다. 요약은 흐름 3줄까지만. 코드·파일은 쓰지 않는다(작업 세션이 같은 문서를 쓰고 있다). 30분 안에 끝낸다. 화면이 작으니 한 번에 한 화면 분량으로 답한다.
1. `date`로 시작 시각을 본다. 과제 안내·기준 문서·데이터 목록을 본다. 데이터는 `head`·`wc`로만.
2. 지도를 보여준다:
   - 흐름 3줄: 입력 → 처리 → 출력, 누가 무엇을 하나(원문 위치)
   - 요구 목록: 필수/선택과 원문 위치
   - 결과를 쓰는 사람·이해관계자(원문에 있으면)
   - 낯선 용어 목록(풀이 없이)
   - 읽을 순서: 파일·절 3개 이내

   안내: "이 순서로 원문을 읽고, 막히는 용어는 물어보세요. 다 읽으면 '다음'." 용어를 물으면 한 줄로 풀고 원문 위치를 붙인다. 개념은 실제 데이터 한 행과 기준표 행을 나란히 놓고 설명한다. 질문에 답할 때마다 끝에 "지금 읽을 곳: …" 한 줄을 붙인다.
3. 규칙이 두세 개 걸리는 평범한 입력 후보 2~3개를 한 줄씩 보여주고 고르게 한다("알아서"면 네가 고른다).
4. 그 건의 원문 행을 보여주고, 처리 단계 전체를 표 하나로 보여준다: `단계 | 규칙(원문 위치) | 이 건의 값`. 처음 나온 용어·산식은 칸 안에 한 줄로 푼다. 단계마다 멈추지 않는다.
   이어서 판단이 갈리는 지점 2개만 묻는다(기준 문서만으로 결론이 안 나거나 틀리기 쉬운 곳). 답하면 대조하고, "모름"이면 바로 값을 보여준다.
5. 끝나면 작업 세션에 붙여넣을 블록 하나를 출력하고 "이 블록을 작업 세션에 붙여넣으세요. 작업 세션이 기준 건을 SPEC에 반영하고 담당자 질문을 정리합니다"라고 안내한다:
   - 용어: `용어 | 뜻 | 원문 위치`
   - 담당자 질문 후보: 기준 문서로 답이 안 되는 지점과 해당 데이터 건수
   - 기준 건: 입력 식별자 · 단계별 값 · 최종 결과(최소 흐름의 기대값이 된다)
