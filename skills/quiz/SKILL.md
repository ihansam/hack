# quiz — 작업 기록 기반 자기 점검

## 1. 근거 읽기 (짧게)
`git log --stat`, `DECISIONS.md`, `FLOW.md`, `SPEC.md`의 질문·담당자 답, 핵심 코드의 해당 부분만. 통째로 읽지 않는다.

## 2. 문항 2~3개
아래 유형 중 이번 작업에서 설명이 가장 약할 것 같은 곳을 2~3개 골라 낸다. 사람이 더 원하면 다른 유형으로 이어 간다. 모두 이 작업의 실제 기록에 근거한다. 일반론으로 답할 수 있는 문항은 내지 않는다.
1. 결정·근거 — 실제 결정 하나: 왜, 무엇을 버렸나. 가능하면 에이전트가 정한 것을 고른다(누가 정했는지도 답해야 한다)
2. 흐름 — 어떤 입력이 어느 단계(읽기/정제/계산/판정/저장/화면)를 거쳐 어느 결과가 되나. 단계 이름으로 답해도 맞게 본다
3. 실패·리스크 — 이런 입력·상황이면 출력·화면이 어떻게 되나, 깨지는 조건
4. 검증 — 그 확인이 실제로 보장하는 것과 못 하는 것
5. 담당자 대화 — 답을 어디에 어떻게 반영했나, 묻지 않은 모호성이 결과에 어떻게 드러나나
6. 전제 왜곡 — 실제 구현과 다른 전제를 깐 문항. 한 번 할 때 하나쯤 섞고, 어느 것인지 표시하지 않는다

문항 규칙: 줄 번호·ADR 번호·커밋 해시를 쓰지 않는다. 대상은 데이터 값이나 결정 내용으로 가리킨다. 경로·함수명은 문항당 1개까지. 하위 질문은 1~2개. 몇 문장으로 타이핑해 답할 분량. 파일·함수를 순서대로 나열하라는 식의 회상 문항은 내지 않는다.

## 3. 진행 — 한 문항씩
1. 문항을 보여주고 "안다 / 모른다"를 묻는다.
2. **모른다** → 바로 모범답을 보여준다.
3. **안다** → 사람이 한 줄 쓰게 하고 대조한다: 맞음 / 틀림 / 빠진 것. 기억 착오(누가 말했나, 누가 정했나)를 특히 본다.
4. 모범답 형식: ① 첫 문장 = 직답(전제 왜곡이면 전제를 바로잡는 문장) ② 근거 위치 — 원문·실행 결과·코드 파일. 에이전트가 쓴 문서만 가리키지 않는다 ③ 한계 한 줄. 결정 문항은 `[사람]`/`[agent]` 중 누가 정했는지 밝힌다.

## 4. 끝
틀렸거나 모른 문항의 근거 위치만 목록으로 보여준다. 파일은 만들지 않는다.
답할 때 규칙을 한 번 상기시킨다: 백지로 두지 않는다 — 모르면 원리로 첫 문장을 쓰고 `[구현 미확인]`을 붙인다. 질문의 전제부터 의심한다.
