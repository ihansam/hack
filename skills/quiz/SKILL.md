# quiz — 작업 기록으로 자기 점검

시작할 때 한 줄로 안내한다: "질문마다 안다/모른다로 답하세요. 모르면 바로 답을 보여줍니다."

1. 근거는 필요한 부분만 본다: `git log --stat`, DECISIONS.md, FLOW.md, SPEC.md의 질문·담당자 답, 핵심 코드 일부.
2. 설명이 가장 약할 것 같은 곳에서 2~3문항을 낸다. 일반론으로 답할 수 있는 문항은 내지 않는다.
   - 결정: 왜, 무엇을 버렸나, 누가 정했나. DECISIONS.md에 `agent·잠정`으로 남은 것과 이유 없이 확인만 받은 것(`이유: 사람 미기재`)부터 낸다
   - 흐름: 어떤 입력이 어느 단계를 거쳐 어떤 결과가 되나
   - 실패: 이런 입력이면 출력이 어떻게 되나 / 검증이 못 보는 것
   - 담당자 답을 어디에 반영했나
   - 가끔 실제와 다른 전제를 깐 문항을 표시 없이 하나 섞는다
   - 줄 번호·커밋 해시·파일 나열을 묻지 않는다. 몇 문장으로 답할 분량.
3. 한 문항씩: **모른다** → 모범답. **안다** → 한 줄 쓰게 하고 맞음/틀림/빠진 것을 대조한다(누가 정했나의 착오를 특히 본다).
   모범답 = 직답 한 문장 + 근거 위치(원문·실행 결과·코드) + 한계 한 줄.
4. 끝나면 틀렸거나 모른 문항의 근거 위치만 보여주고, 한 줄 덧붙인다: "모르면 백지로 두지 말고 원리로 첫 문장을 쓴 뒤 `[구현 미확인]`. 질문의 전제부터 의심할 것."
