# hack

시간 제한이 있는 데이터·코드 과제를 코딩 에이전트(Codex)와 함께 할 때 쓰는 작업 규칙과 스킬.
과제 답이나 과제별 코드는 들어 있지 않다.

## 에이전트에게 — 설치

"ihansam/hack 받아서 README대로 해줘"를 받았다면 **작업 폴더 루트에서** 아래만 실행한다.

```bash
git clone --depth 1 https://github.com/ihansam/hack /tmp/hack 2>/dev/null || git -C /tmp/hack pull -q
bash /tmp/hack/install.sh
```

- 작업 폴더 안에 clone하지 않는다(키트의 git 이력이 작업 이력에 섞이지 않게).
- **두 명령은 처음부터 샌드박스 밖(승인 요청)에서 실행한다.** Codex 샌드박스는 네트워크와 `.agents/`·`.git` 쓰기를 막아서, 안에서 돌리면 AGENTS.md만 복사되고 스킬·commit이 빠진다.
- `install.sh`가 "설치 미완"으로 끝나면(종료 코드 1) 샌드박스 밖에서 한 번 더 실행한다.
- 출력을 그대로 보고하고, 마지막 **"사람이 할 일"**을 그대로 전달한다. 그 외에는 아무것도 하지 않는다.

## 구성

| 경로 | 내용 |
|---|---|
| `AGENTS.md` | 큰 틀만: 소통(짧게, 다음 할 일 안내), 흐름 6단계, 문서 5종, commit·환경 규칙 |
| `skills/drill` | 첫 1시간. 문제 파악·전략·계획을 이끌고, 사람은 새 창에서 원문 지도를 받아 직접 읽고, 입력 한 건을 원문부터 결과까지 따라간다 |
| `skills/quiz` | 마감 전. 작업 기록으로 확인 질문 2~3개, 안다/모른다로 대조 |

`install.sh`는 `AGENTS.md`(과제가 준 것이 있으면 끝에 덧붙임)와 스킬을 `.agents/skills/`에 넣고, uv가 없으면 설치하고, 추가한 파일만 commit한 뒤, 지침 파일 목록·크기·git 루트를 출력한다(override 파일이나 32KiB 상한에 규칙이 묻히지 않았는지 점검).

## 설계 메모

- **사람은 절차를 외우지 않는다.** `$drill` 하나로 시작하면, 그다음 할 일은 에이전트가 단계마다 안내한다.
- **큰 틀만 정한다.** 흐름·문서·금지선만 두고 세부는 에이전트가 정한다.
- **이해는 작업 중간에 나눠 둔다.** 초반에 원문 읽기와 한 건 따라가기, 최소 흐름 뒤 기대값 대조, 1/3 시점 결정 확인, FLOW 한 단계 확인, 마감 전 quiz.
